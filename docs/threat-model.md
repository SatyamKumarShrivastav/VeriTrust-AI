# VeriTrust AI — Threat Model & Security Posture

## 1. Assets to Protect
1. **Evidence Media Integrity:** Preventing unauthorized modification, tampering, or silent corruption of uploaded evidence files.
2. **Cryptographic Signing Keys:** Protecting Ed25519 private keys against exfiltration.
3. **Chain of Custody Immutability:** Ensuring historical transfer events cannot be rewritten.
4. **User Credentials & RBAC Tokens:** Protecting bcrypt password hashes and JWT secrets.
5. **Report Authenticity:** Ensuring forensic reports reflect verified facts without AI hallucination.

---

## 2. Threat Analysis & Mitigations

| Threat | Risk Level | Architectural Mitigation in VeriTrust AI |
|---|---|---|
| **Post-Registration File Tampering** | Critical | SHA-256 chunk-based dynamic recalculation. Any single-byte modification causes immediate `INTEGRITY MISMATCH` detection. |
| **Manifest Falsification / Spoofing** | High | Ed25519 digital signatures. The manifest is signed at ingestion. Modifying any field invalidates the cryptographic signature. |
| **Key Exposure in Source/Logs** | Critical | Private keys are loaded strictly from external PEM paths defined via environment variables. Private keys are never returned in API responses or persisted in DB. |
| **History Rewriting in Custody** | High | Chain of custody uses hash chaining (`event_hash` includes `previous_event_hash`) plus on-chain anchoring via Ethereum smart contract. |
| **Generative AI Hallucination** | High | The LLM does not determine verification pass/fail status. A structured JSON schema generated by deterministic verification logic is the single source of truth. |
| **Path Traversal in Uploads** | High | Original files are renamed to server-generated UUID/evidence IDs (`EV-YYYY-NNNNN.ext`) on disk. Original filenames are stored as metadata only. |
| **Unauthorized Evidence Access** | High | Fast-path JWT dependency checks enforce ownership or Administrator/CEO role before serving evidence files or metadata. |
| **Offline Blockchain Node Failure** | Medium | System gracefully reports ledger status as `unavailable` or `pending`. It never fabricates false transaction confirmations. |

---

## 3. Forensic & Ethical Safeguards
- **No Absolute Truth Claim:** A matching SHA-256 hash proves the file matches the registered reference; it does not prove the captured scene is truthful.
- **Model Uncertainty Disclosure:** VeriFace detection outputs include clear limitations notices and confidence intervals.
- **Human in the Loop:** Generated forensic reports require qualified human forensic review prior to courtroom or disciplinary submission.
